# PRO273 private primitives ABI

Status: source contract only; build, installation and runtime qualification are not established. PostgreSQL 17.6, ICU 78.1 and double-conversion 3.3.1 are API references, not installed facts. Inputs, toolchain, exact internal PostgreSQL ICU ABI and execution environment require independent qualification.

The optional Windows-only `PRO273_INSTALLER_ROOT` CMake target uses a separate preprocessor branch before the PostgreSQL and ICU headers. Its service entry always reports access denied; no receiver is launched. The closed-registry reader checks the raw authority key against the declared and independently supplied SHA-256 pins. It also compares the authority epoch and floor, installation generation, validity window, host and boot identity, service SID, reservation and closure hashes to the supplied expected snapshot. The installer still needs an authenticated producer for that snapshot and clock, registry custody and ancestor checks, effective token rights, and actual process and loader identity. Startup receipt verification, complete registry/SCM/token/ACL inspection, funding, fences and inherited channel remain incomplete. The compiled in-memory checks do not establish installation or startup qualification.

The unreachable security observation now accepts an already reserved caller-owned workspace, an independently qualified descriptor limit, and a shared prepaid ACE-event allowance. It rejects workspace sizes above the 65,536-byte pre-authentication ceiling or the qualified limit, requires allowance for the workspace's maximum possible ACE headers before querying, spends an event per examined ACE, and never retries or allocates on a size failure. Its handle-based kernel, registry and service queries are unqualified source only; no file-specific acquisition is qualified and the kind tag does not prove the handle's type. The budget values are not proof of funding: the missing verifier must authenticate their origin, account for the query and validation costs and overlapping storage, and preserve charges and held-object identity. Effective rights, owner rights, parent replacement rights, privileges, mutation and same-size descriptor changes remain unresolved. A successful observation is not an access decision or admission.

The uncalled SCM observation owns its fixed manager and service handles until owner destruction, including after failure, and spends caller-provided open, handle and observation allowances. It compares bounded configuration strings with the fixed service account and an externally supplied expected image value, queries failure actions and service SID mode, and compares the fixed account lookup SID with the anchor's canonical SID. The expected image is only a comparison input; its authenticated manifest provenance, command-line encoding and link to the held executable are not established. The retained SCM handles do not by themselves prove object incarnation or protect configuration from mutation. The authenticated anchor, actual token/account and PID/creation identity, independent manager/service identity, counter and stack provenance, security checks and effective rights remain mandatory unresolved joins; the identity and rights placeholders deny. SCM API behavior and resource accounting have not been compiled or run. No admission or service-entry behavior changes.

The uncalled token observation requires a separately retained, stable output slot that does not overlap its workspace, counters, anchor or budget. It preserves the opened token for caller cleanup even when later observations fail. Before any qualification gate can be removed, an independently established policy must cover disabled privilege LUIDs and token groups, and independently authenticated proof must establish the token handle's access. Neither proof is established by the current source; the qualification, process-binding and effective-rights gates continue to deny. These source checks do not establish storage ownership, funding, compilation or runtime behavior.

The unreachable held-path observation accepts caller-owned component and path buffers and independently prepaid open, retained-handle and observation counters. It requires the handle slots for all path components to be initialized to `INVALID_HANDLE_VALUE`. It rejects occupied slots before changing the retained count or spending counters. It opens canonical drive-path prefixes, retaining successful handles for caller cleanup. A separate uncalled SHA-256 observation reads the retained file handle into caller-provided storage, compares an expected volume/file identity, metadata, length and digest, and observes metadata before and after. Read calls and bytes, hash operations, observations, handle slots and externally qualified stack are separately bounded; attempted operations are spent. The SHA-256 provider, hash-object storage, cursor exclusivity, stack and counter provenance require independent qualification. Its expected identity is only a structure; no authenticated manifest decoder supplies it yet. The target now links bcrypt, which also requires independent qualification.

The Windows source compiles to an object. Live directory-entry, immutable content and loader identity checks still require qualification. Existing writable handles, aliases, mutation and ACLs remain unresolved; the directory-entry linkage placeholder always denies. A fresh pathname open or matching metadata is not linkage proof. No authenticated budget, manifest or loader chain exists, and no caller can use these observations for admission. Failure leaves opened handles with the caller; no retry or refund is authorized.

The uncalled process observer checks the PID, creation time and liveness of a retained process handle before and after reading its executable path and module paths. It compares the paths against the caller's expected set, checks the module handle list again, and spends one prepaid query for each attempted Windows API call. It uses caller-owned buffers and rejects incomplete results. A matching snapshot covers the paths reported by Windows during the check. Mapped-file identity, loader continuity and later module loads still require independent evidence.

The source-only channel transcript consumes six frames with sequence numbers 1–6, consistent with the existing TypeScript contract. Its callback supplies data only: it cannot establish ownership of a pipe or absence of late frames. Actual psql identity and committed delivery expected values must be captured in separate owner-controlled later snapshots; there is no success authority before those snapshots exist. The one-shot exchange fails on reentry, including when a callback ignores the nested failure. This transcript does not change the unconditional service or admission denies.

The separate uncalled v2 source model validates eight canonical framed envelopes in fixed buffers, with per-stage sender and ACK sequencing, a modeled SQL-work marker after stage 5, and phase-specific clean EOF after stages 7 and 8. It owns exact correlation snapshots as values become available: initial binding and limits at HELLO, permit at stage 2, fence at stage 3, psql PID at stage 4, creation time, image and snapshot hash at stage 5, and delivery and input at stage 6. Later substitution fails; these supplied values are not authentication. Creation times and input length are positive canonical uint64 values. The complete envelope is bounded by the smaller of 4,096 bytes and the qualified maximum; smaller sufficient frames are allowed. It checks canonical padded base64 and pad bits before decoding, and checks SHA-256 correlations for snapshots and receipt bytes. Its receipt size is separately bounded at 3,072 bytes and must be independently qualified. Failure, early EOF, reentry or a repeated event poisons the model; it does not negotiate or fall back to v1. Calls must be serialized by a single owner; the model is not thread-safe, takes no transport callback and does not own a native handle. A stage 5 snapshot and a COMMITTED outcome are untrusted claims, not process identity, SQL authentication, a fixed receipt ABI, publication proof or permission to dispatch. Original-parent liveness, one-use grant/fence, receipt authentication, exact retained SQL session and bytes, issuer, funding, actual I/O and containment remain unimplemented and unqualified. The unconditional service and admission denials remain; no build or runtime claim follows from this source.

The disconnected v2 byte adapters model fragmented input, a four-byte little-endian body length, and one owned frame at a time. Before stage 7, a feed returns the exact consumed prefix and the caller retains any coalesced suffix until offers, partial write acknowledgements and applicable barriers complete. A feed completing stage 7 or 8 with a suffix fails permanently, since that sender must reach clean EOF. Offers are copies, and each ACK applies only to the currently offered direction and range; zero-progress and total operation ceilings are cumulative. EOF is an explicit clean event. Errors, reentry and terminal replay poison the adapter. The native caller must provide valid, stable extents, nonoverlapping outputs and qualification slices, and serialized calls; pointer accessibility and concurrent mutation cannot be proven by this source model. No handle, actual transport, SQL execution or installation is provided.

Resource qualification must account simultaneously for the native adapter's 4,096-byte frame, the validator's 4,096-byte frame and 3,072-byte receipt buffer, six 1,024-byte snapshot slots, snapshot candidate and 4,096-byte hash preimage stack buffers, SHA/parser stack and metadata, plus caller input, suffix and offered output. The Node model additionally holds its owned frame, a complete validation copy, decoder body and receipt copies, canonical strings and parsed/snapshot objects, returned offer copies and caller-owned inputs/suffixes; runtime overhead, temporary allocations, retained caller copies and concurrency require independent measured bounds. The supplied ceilings and counters are not qualified funding or a reservation.
Text operands and results are explicit-length UTF-16BE code units in BYTEA; empty values, NUL, lone surrogates and astral pairs are retained. Binary64 values are exactly eight big-endian bytes. These representations do not imply that all values can be published to existing native JSONB state.
