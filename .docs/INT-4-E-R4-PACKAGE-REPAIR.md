### Historical Security pre-edit block that shaped P2/P3

The P2 loader method is still a design decision. `--library-path` alone permits glibc RPATH/RUNPATH, `/etc/ld.so.preload`, cache, default directories and hardware-capability selection to load host code before JavaScript. A reviewed hermetic method must deny a missing packaged SONAME even when the host has a copy, before any host constructor executes. Test preload, cache, default, RPATH/RUNPATH and hardware-capability cases on the exact supported Linux environment; a post-load inventory is too late for this boundary.

P3 must run its executable measurement in the **actual issuer CLI before reading credentials**. Recheck approved membership after later CommonJS, ESM or native loads and immediately before proof insertion. Prove an exclusively CommonJS graph and reject other import mechanisms, or explicitly measure ESM; `require.cache` alone does not cover ESM. A separate test probe may exercise the same function but cannot replace the production-path check.

The manifest contract must enumerate allowed directory prefixes and every regular file, rejecting unexpected empty directories as well as unlisted files. Set finite entry, depth and byte limits and repeat inventory at launch and before insertion. The launcher cannot validate its own hash by embedding that hash in itself; a separately custodied, independently verified run generation or trusted service pin must bind launcher SHA, manifest SHA, layout SHA and source/trust generation in an acyclic order. Security must review those exact bindings before P2/P3 implementation.

### Selected P2/P3 boundary for disposable synthetic draft

Use a **disposable, operator-built, read-only ext4 `RootImage=`** with a pinned service unit for the private Linux proof. The image contains the versioned package at its fixed absolute path and an explicit minimal filesystem skeleton. It contains no `/etc/ld.so.preload`, `/etc/ld.so.cache`, default-directory libraries, host checkout bind mount or host library bind mount. The issuer runs without root, namespace-changing capabilities or inherited host directory descriptors. Required `/proc`, device and later credential mounts must be enumerated separately and cannot become code search paths. This boundary is a proposal for Security review, not permission to deploy a service or mount credentials.

The package preflight rejects nonempty or external RPATH/RUNPATH, external absolute `DT_NEEDED`, unexpected hardware-capability directories and any loader or preload configuration outside its fixed policy. The pinned loader receives a package-only library path, cache inhibition and a fixed supported hardware-capability mask. An external operator receipt pins the root-image, service-unit, launcher and package-manifest digests. A separately custodied run generation binds that receipt plus issuer source, trust and revocation digests. Build order is payload → manifest → launcher → external receipt → run generation; no artifact hashes itself.

Before any JavaScript, prove the actual CLI starts from the image; a host-only preload library cannot run; and removing a required packaged SONAME, while retaining a matching host copy and updating only the test fixture manifest, fails without a host constructor. Package-local preload/cache/RPATH/hardware-capability manipulation and an unlisted `.so` must fail in preflight. Record mount topology, inherited descriptors and mapped paths with marker results. Do not alter host preload settings for a test.

For the actual issuer CLI, move executable measurement before credential access. Track both CommonJS and ESM loads from a verified bootstrap before importing external application modules; permit only built-ins and manifest-listed canonical file modules. Reject external URLs, aliases, unreviewed worker/subprocess paths and unexpected native mappings. Load the generated Prisma client and native engine without a database connection if that version supports it, then measure package membership and mapping device/inode. Keep tracking active and repeat verification after lazy/native loads and immediately before proof insertion. A credential-free actual-CLI run must show successful measurement followed by missing-credential denial and no earlier credential or network access; a separate probe is diagnostic only. If the engine cannot be loaded offline, that gap stays open.

The assembler and launcher use versioned finite inventory limits: at most 16,384 regular payload files, 4,096 directories, depth 32, 4,096-byte canonical relative paths and a 4 MiB manifest. Per-file and aggregate byte ceilings require measurement of the actual package before freezing the format. Every directory prefix is enumerated; unexpected empty directories, unknown file types, duplicate identities, symlinks and hardlinks fail. Recheck the inventory at launch and before insertion. Exceeding a bound requires reviewed format revision, never truncation.
